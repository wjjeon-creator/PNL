# 7월 대시보드 채우기 + 계약 유형별 수익성 인사이트

Status: Implemented
Source data: `'26년 7월 대리점 수익성 분석.xlsx` (사용자 Downloads 폴더, 2026-08-11 전달)

## 배경

- 6월 대시보드(`index.html`)는 2026-07-29~30 세션에서 사이드바(월) + 서브탭 3개(수익성 요약 / 대리점 상세 / 상생 프로모션 충족률) 구조로 재구성됐다. 7월 패널은 그동안 "데이터 대기" 스켈레톤 상태였다.
- 이번 요청은 원래 "대리점 상세 탭에 계약 유형별 수익성 섹션 추가"였으나, 실제 7월 원자료를 열어보니 요약·대리점 상세·프로모션에 필요한 전체 데이터가 이미 한 파일에 있어, 범위를 "7월 대시보드 전체 채우기"로 확장하기로 사용자와 합의했다.
- 계약 유형별 수익성은 2026-07-29에 삭제됐던 "계약 유형별 상세" 탭(B2B 6개사 하드코딩 vs 일반, 커밋 `e2c6389`)과 다른 개념이다. 그 탭은 인사이트 부족으로 삭제됐다. 이번엔 별도 탭이 아니라 대리점 상세 탭 안의 섹션 하나로, 그리고 하드코딩된 6개사 목록이 아니라 원자료에 실제로 존재하는 `계약 유형` 필드를 그대로 쓴다.

## 목표

1. 7월 패널의 3개 서브탭(요약/대리점 상세/프로모션)을 6월과 동일한 구조·톤으로 실데이터 채우기
2. 대리점 상세 탭에 "계약 유형별 수익성" 섹션 신규 추가
3. 모든 합계·비율·순위는 원자료에서 직접 계산 (하드코딩 금지 — 6월의 충족률 구간 분포 오류 재발 방지)

## 비목표 (Out of scope)

- 파일 업로드 → 자동 분석 기능 (별도로 중단된 설계, `pnl-upload-feature-design-stalled` 메모리 참조) — 이번 작업은 여전히 6월처럼 손으로 데이터 객체를 작성하는 방식
- 보상 티어 정책의 재계산/시뮬레이션 — 정책 표는 참고용으로만 노출하고, 대리점별 최종 보상금은 원자료의 계산값을 그대로 신뢰한다 (아래 "의도적으로 하지 않는 것" 참조)
- 8~12월 탭 변경 없음

## 섹션 3 — 상생 프로모션 충족률

**주의**: 이 시트의 집계 기간은 "5/18~6/30 기준"으로, 7월 달력 기준 신규 설치가 아니라 6월까지 누적된 프로모션 조건 달성 현황이다(6월 대시보드의 "마감 7/31" 프로모션과 같은 캠페인의 후속 집계). 대리점 상세의 "7월 실적·순매출"과는 별개 기간 기준이므로, 화면에는 6월과 동일하게 "상생 프로모션 충족률" 캡션만 쓰고 "7월 실적"이라는 표현은 쓰지 않는다.

**퍼널**: 설치 600 → 토스페이 청약 569 → 통합결제 5건 이상 509 → 조건 달성 493. 전체 충족률 82.17%(6월 65.7%에서 개선). 이탈이 가장 큰 구간(청약→결제, −60건)을 6월과 같은 방식으로 강조.

**KPI**: 확보(조건 달성) 493건 · 34,510,000원 / 미충족 107건 · 16,050,000원(잔여, 마감 전 확보 가능분).
